Studio Couverture AI — Documentation

Thank you for purchasing Studio Couverture AI — a commercial book cover generator for Amazon KDP (ebook & print), built with vanilla HTML/CSS/JS, Tailwind CSS, Firebase, and Stripe. No build step, no framework required — just static files you can host anywhere.

This item assumes no prior coding experience beyond copy-pasting configuration values. If you get stuck, see the "Support" section at the end.

2. Quick start (no backend)

Upload the project as-is to any static host (GitHub Pages, Netlify, Vercel, your own server). The app runs immediately in Demo Mode: AI generation and credit purchases are simulated locally so you can preview the design and KDP calculator right away.

3. Enabling real AI generation & payments

3.1 Create a Firebase project

  1. Go to console.firebase.google.com and create a new project.
  2. Enable Authentication → Sign-in method → Anonymous.
  3. Enable Firestore Database (start in production mode).
  4. Upgrade to the Blaze (pay-as-you-go) plan — required to deploy Cloud Functions that call external APIs.
  5. Project settings → Your apps → Web app → copy the config object.

3.2 Configure the client

Open assets/js/firebase-config.js and paste your project's values into the FIREBASE_CONFIG object. The app automatically switches out of Demo Mode once this file contains real values.

3.3 Get a Gemini API key

Create a key at aistudio.google.com/apikey. This powers the AI cover illustration feature (Gemini 3.1 Flash Image).

Important — image generation billing: unlike Gemini's text models, image generation models have little to no free daily quota through the API (testing in AI Studio itself is free, but programmatic API calls are billed). To use the AI illustration feature in production, enable Cloud Billing on the Google Cloud project tied to your API key (AI Studio → API keys → your project → Upgrade). Pricing is per generated image — check ai.google.dev/gemini-api/docs/pricing for current rates. The rest of the app (cover editor, KDP calculator, exports) works fully without this.
This item's backend (AI generation + payments) runs on a Cloudflare Worker instead of Firebase Cloud Functions. This means you do not need to upgrade to the Firebase Blaze (pay-as-you-go) plan or add a billing card — the free Firebase plan (Spark) is enough, since Firebase is only used here for Authentication and Firestore storage.

3.4 Get a Firebase service account key

The Worker needs admin-level access to your Firestore database (to credit users after payment) without going through client-side security rules.

  1. Firebase Console → ⚙️ Project settings → Service accounts tab.
  2. Click Generate new private key → confirm → a .json file downloads.
  3. Keep this file safe — it grants full admin access to your Firebase project. You'll paste its full contents into a Cloudflare secret in the next step.

3.5 Create the Cloudflare Worker

  1. Create a free account at dash.cloudflare.com — no credit card required.
  2. Workers & Pages → Create → Create Worker → give it a name (e.g. studio-couverture-worker) → Deploy.
  3. Click Edit code → delete the default sample code → paste the entire contents of cf-worker/worker.js from this package → Save and deploy.
  4. Go to Settings → Variables and Secrets → add each of the following as a Secret (click "Encrypt"):
VariableValue
FIREBASE_PROJECT_IDYour Firebase project ID (plain variable, not secret)
FIREBASE_SERVICE_ACCOUNTFull JSON contents of the service account file from step 3.4
GEMINI_API_KEYFrom step 3.3
ALLOWED_ORIGINYour site's URL, e.g. https://youraccount.github.io (plain variable)
STRIPE_SECRET_KEYOptional — see step 3.6
STRIPE_WEBHOOK_SECRETOptional — see step 3.6
NOWPAYMENTS_API_KEYOptional — see step 3.7
NOWPAYMENTS_IPN_SECRETOptional — see step 3.7
NOWPAYMENTS_IPN_URLOptional — your Worker's URL + /nowpayments-webhook

Copy your Worker's public URL (shown at the top of the Worker's dashboard page, format https://NAME.YOUR-SUBDOMAIN.workers.dev) into assets/js/worker-config.js as WORKER_URL.

3.6 Set up Stripe (card payments)

  1. Create an account at dashboard.stripe.com.
  2. Get your Secret key from Developers → API keys (starts with sk_) → add it as STRIPE_SECRET_KEY in the Worker.
  3. Developers → Webhooks → Add endpoint → URL: your Worker's URL + /stripe-webhook → listen to checkout.session.completed → copy the Signing secret (starts with whsec_) → add it as STRIPE_WEBHOOK_SECRET.
  4. Edit credit pack pricing directly in cf-worker/worker.js under the CREDIT_PACKS object if you want different amounts or prices (redeploy the Worker after editing).

3.7 Set up NOWPayments (optional — crypto payments)

This item also includes a ready-to-use crypto payment option (BTC, ETH, USDT and 300+ coins) via NOWPayments — useful for buyers/customers in regions with limited card payment access.

  1. Create an account at nowpayments.io.
  2. Dashboard → API Settings → generate your API key → add as NOWPAYMENTS_API_KEY.
  3. Dashboard → Store Settings → Instant Payment Notifications → generate your IPN Secret key → add as NOWPAYMENTS_IPN_SECRET.
  4. Set both the NOWPayments dashboard's IPN callback URL and the Worker's NOWPAYMENTS_IPN_URL variable to your Worker's URL + /nowpayments-webhook.

If you don't want to offer crypto or card payments, simply leave the relevant Worker variables empty — the corresponding button will show a friendly configuration message instead of erroring out.

5. Rebuilding the Tailwind CSS file

If you add new Tailwind classes not already used in the project, regenerate assets/css/tailwind.min.css:

npm install -D tailwindcss@3
npx tailwindcss -i ./input.css -o ./assets/css/tailwind.min.css --minify

(Create a minimal input.css with @tailwind base; @tailwind components; @tailwind utilities; and a tailwind.config.js pointing content at your HTML files.)
